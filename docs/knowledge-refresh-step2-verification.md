# 知识库刷新第二步：分批发现与 SQL 清单分页

## 实施范围

第二步在第一步“缓存先返回、后台核验、同库刷新保留窗口”的基础上增加独立目录清单。内容索引仍使用现有 documents / LanceDB 提交协议；本次没有重建内容索引，也没有实现第三步的持久内容任务队列。

### 目录发现与对账

- `opendir()` 流式枚举，不先用 `readdir()` 构造整棵目录树。最多 200 个条目或约 150ms 提交一批；进入子目录也会先提交已积累的批次。
- 批次提交后通过 `onCatalogBatch` 接入 `ScanUpdates`，约 200ms 合并通知页面。已有窗口保留，新增路径可以在整树遍历与全文处理完成前显示。发现文案表示“已发现”，不表示最终文件总量。
- 元数据在路径可见后处理，本地最多 4 路、远端索引最多 2 路，约 32 条一批提交；SQL 事务内没有源文件、哈希、Office/OCR 或向量等待。
- 扫描使用独立 run id、根 dev/ino、完整枚举目录及其身份；新扫描使旧代际失效。中断保留此前已提交批次，不按未完成扫描对账。
- 清理前重新检查根和共享身份；失败/符号链接/不可访问范围被排除。未见的 pending/异常条目分批复查存在性、成功枚举的祖先身份和行 revision，再执行条件删除。枚举后重新出现的文件保留。
- 内容删除仍保留原有源存在性、标签、移动识别和旧内容版本保护。生产守卫没有为测试放宽。

### SQL 清单与分页

- 新增 `source_files`、`source_directories`、`source_scan_runs`、`source_scan_directories`，独立 `source_catalog_meta` 管理迁移和清单版本。原数据库 `PRAGMA user_version` 仍为 6。
- 正常、pending、异常按路径统一投影，`file_id` 在 pending → indexed、失败恢复和已识别移动时保持稳定。内容 hash 和向量覆盖不会因为清单存在就被认定有效。
- 名称、加入时间、索引时间、类型、大小、修改时间排序都有 SQL 索引；未知大小/时间始终置后，最终使用稳定 `file_id` 破同值。
- 页面查询、总数、清单版本来自同一 SQL 读快照；侧栏概览也在自己的单一 SQL 快照中读取。目录前缀用边界范围，不使用可能把 `notes2` 混入 `notes` 的模糊匹配。
- 上下翻页使用带筛选指纹的双向游标，跨目录/排序游标会被拒绝。刷新窗口支持路径锚点与尾部回填；前端切库清理游标和清单版本，拒绝旧版本结果及旧文件身份/修订状态。
- 页面与定位不再进入旧的全库 JS 组装/元数据读取/排序路径；内容队列不会阻塞清单页面。目录计数由条目变更增量维护；标签计数由 SQL 聚合。
- 持久触发器使用 SQLite 内建表达式，不依赖连接内注册的 JS 函数，因此普通独立 SQLite 连接仍能写入。已增加旧 v6 数据、标签与向量文件标记的增量迁移回归；未来清单版本拒绝打开，不自动替换。
- 首次迁移中的空目录/显式目录计数使用一次祖先聚合和带主键的临时计数表，不再对每个目录触发全树重算；目录改名触发器只对新旧祖先做增减。2,500 个空目录的 v6 迁移回归耗时约 98.45ms，并断言全部空目录及祖先计数准确。

## 行为差异与测试调整

1. **分页只查 SQL**：源文件的实时属性由发现或后台核验更新，不再通过“再取第一页”隐式读取整个资料库。原元数据测试改为显式后台核验后，仍断言排序、mtime、缺失属性为 null，以及源文件内容未被改写；缓存重开测试显式准备元数据后，仍禁止分页访问源文件。
2. **名称排序的明确变化**：当前 SQL 名称键使用 SQLite `lower()` / BINARY 顺序，不再调用旧的 `Intl.Collator('en', { sensitivity: 'base' })`。ASCII 大小写折叠、双向翻页和同值稳定性已覆盖；非 ASCII 大小写、重音、标点的相对顺序可能与旧版本不同，不能声称逐项保留旧区域排序。
3. **目录安全检查先行**：旧扫描替身增加 `opendir` 和新清单协议，并分别记录元数据探测与枚举。相似普通目录必须被探测；元数据拒绝访问后不得继续枚举。没有移除生产检查，也没有简单降低原断言。
4. Composer 的独立 SQLite 写入样本改为所选根内的路径，继续断言唯一文档数、真实最大索引时间、交叉标签总数及不打开向量引擎。

## 尚未实现或未实机验证

- 持久内容任务队列、崩溃后续做、提取与发现并行调度属于第三步。本次内容任务仍在整树发现和元数据阶段之后执行，处理清单仍会在内存中保留并按大小排序；不能把这称为完整持久流水线。
- 深偏移 OFFSET 与锚点排名仍可能扫描较多 SQL 索引项；侧栏目录树也未虚拟化。因此首屏变快不等于所有大目录操作都已常数时间。
- 只保证已打开且清单可读的离线缓存浏览，未实现远端重启后离线打开缓存。
- Windows 原生选择器、真实 SMB 断线/重映射、Windows 非 ASCII 大小写和 Finch 宿主内 Office 预览未实机验证。Windows/Linux 路径分支使用可控文件系统替身，不冒充真实设备测试。
- 本次不提交、不推送、不发 npm，也不覆盖或自动启用用户现有安装。此前安装包、未提交文件和 `stash@{0}` 保留。
