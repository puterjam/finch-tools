# 知识库刷新链路：第一步实施与验证

版本：0.25.3，交付名 `finch-knowledge-0.25.3-catalog-first.fapp`。

## 结论与范围

本步已解除**现有清单显示**与内容／向量校验之间的等待，并修复同库通用刷新清空列表。**不是整份增量目录设计已经完成，也不代表大库性能问题全部解决。**

- 分页、定位和窗口刷新先查询已打开库的 SQL 清单；清单读取不等待内容写队列、文件哈希、逐文件元数据、根目录探测或 LanceDB 覆盖计数。
- 源可用性与覆盖核验在回复清单后进行，按小批次推送行状态。未核验前不报告 ready；离线时不伪造覆盖成功。
- 同库 changed 更新保留旧行、计数和阅读位置，返回新快照后才替换；跨库仍隔离旧数据。页面核验取消、库版本、状态版本与当前文档哈希共同拦截迟到结果。
- SQL 新增可选显示元数据缓存。无缓存时大小／时间保持未知，后台补齐；异常文件也能后台取得元数据，不加载向量引擎。显示缓存写失败不改变内容提交或源校验结果。
- 去除默认逐文件固定 25ms 等待，改为协作式让出；扫描中断、暂停、恢复和删除安全守卫保留。
- 顺带补齐 Word／Excel／PowerPoint 独立格式图标及上游许可证；修复完整测试发现的并发旧索引重建竞态：目录准备、符号链接检查与备份重建纳入同一进程内串行保护，并在准备时重新确认源身份。未来版本、损坏数据库仍不自动替换。

## 明确尚未完成

1. **整树发现仍在一次遍历完成后才替换清单**，尚未分批入库、边发现边显示。
2. `browseOrder()` 仍在 JavaScript 构建／排序全集；元数据大集合读取仍非最终方案。10 万条单页仍达约 0.45–1.14 秒，不能声称已实现 SQL 索引分页或常数成本计数。
3. 尚未实施持久化内容任务队列、发现与内容独立调度、崩溃恢复任务或全部元数据快筛；强哈希验证仍保留。
4. 离线保证针对**已打开且清单可读的库**。远端库在应用重启后离线打开缓存，仍需后续架构支持。
5. Windows 原生选择器、真实 SMB 和 Finch 宿主 Office 预览尚未实机验证；浏览器通过不等于宿主已验收。
