# 知识库 0.26.0：管理菜单与提示修正

## 用户可见变化

- 左下知识库菜单只显示名称，不再把完整目录路径作为第二行铺开；悬停名称仍可查看路径。
- 每个库旁增加修改名称和移除按钮，不必先切换到那个库。修改的是显示名称，不修改原目录名称、路径、索引或标签。
- 移除必须经过宿主确认框；“同时删除索引和标签（不删除原资料）”默认不勾选。消息参数中的 `deleteIndex` / `confirmed` 不能绕过这个确认框。
- 不勾选：只移除登记，索引和标签保留；重新添加同一目录可继续使用。
- 勾选：停止该库任务，等待对应原生文件句柄关闭后，仅将该库拥有的索引和标签送入系统回收站。不会删除原资料、其他知识库索引或共享引擎缓存。
- 当前库也可移除；它的旧列表、计数和筛选被清理，初始化页可继续选择其他已登记的库。最后一个库移除后保持未选择状态，不自动创建或打开旧目录。
- 源文件未找到与磁盘／共享／权限暂不可用使用不同提示，通用 `ENOENT` 不再一律误报“已索引的文件在磁盘上找不到了”。缺失提示建议确认位置后扫描更新，不声称文件已被删除。
- 优化中英文工具提示：源路径仅以当前知识库为准，不从聊天工作目录或其他库猜补；不可访问不代表已删除、清理成功或扫描成功。保留原文件的约束不变。

## 数据与安全边界

- 登记修改串行持久化，保存失败不先改内存；重命名与移除可并发发起而不丢失其他库记录。已存在的登记表即便为空也具有权威性，旧选择指针不能在重启后让已移除库复活。
- 删除路径不接受页面传入的绝对路径：本地库只允许根下 `.knowledge`，远端库只允许已记录的、本机 `remote/<32 位标识>` 索引。
- 本地源身份变化、符号链接、未知目录内容、无法确认旧远端索引位置或仍由其他登记库共享的索引一律拒绝删除。可以取消勾选，仅移除登记。旧版远端库可能需要先正常打开一次，以记录索引位置。
- 删除前按索引路径等待所有本实例退役任务与原生句柄关闭；关闭失败不继续删除。
- 索引先在原父目录内暂存到唯一名称，登记保存成功后才送回收站；登记保存失败会恢复索引。回收站失败也尝试恢复索引，并明确报告“已移除但清理未完成”，不冒充完整删除。
- 切库后旧预览失败回调不会在新库发起同名 ID 的打开请求。文件打开也重新核对源目录可用性、已记录的本地根身份及当前库版本；提示本身不删除缓存条目。
- 原文件始终不删除；“完全移除”在此指登记与当前索引、标签均移除，并不是清空源文件夹或系统回收站。历史备份索引及其他库的共享缓存不在删除范围。

## 验证范围

- 新增登记回归在旧实现上先出现 `rename/remove is not a function` 红灯，再实现功能。
- API 回归覆盖名称修改同步到所有面板、取消、默认不勾选、恶意确认参数无效、离线仅移除、当前及最后一个库移除、重启不复活、保存失败恢复索引、共享缓存拒绝删除，以及缺失／断盘提示区分。
- 索引清理回归覆盖可逆暂存、回收站失败恢复、符号链接、未知内容、根身份不符、已知远端离线清理与其他缓存保留。
- 当前 macOS 上实际调用系统回收站 API，使用的全部是测试新建的私有索引；另用可控关闭屏障证明索引不能在原生句柄释放之前移走。没有拿用户真实知识库做删除测试。
- 真实 Chromium 通过页面 DOM 操作验证 520／820／1200px 菜单边界、修改和移除按钮、取消不丢记录、移除当前库后重新选择，以及 60 字符名称省略和操作按钮不被遮挡。确认框字段和默认值由真实后端 API 的宿主替身校验；没有冒充 Finch 原生确认框的视觉实机测试。
- Windows 回收站和 Linux `gio trash` 适配未实机运行；真实 SMB 重映射和断线场景也未实机验证。缺少安全证据时会拒绝索引删除，而不是猜测路径。
